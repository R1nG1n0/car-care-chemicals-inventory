## 1. Общие сведения

### 1.1. Предпосылки

Владелец ухаживает за автомобилем сам и держит дома десятки средств (шампуни, полироли, очистители и т. п.) и инструментов (микрофибры, губки, аппликаторы, щётки). Остатки не видны, поэтому часто покупается то, что уже есть.

### 1.2. Цель

Сайт, на котором за несколько секунд с телефона можно узнать:

- есть ли у меня это средство или инструмент, сколько осталось и где лежит;
- когда, где, сколько и по какой цене я его покупал.

Плюс точный учёт расхода в миллилитрах и штуках и список того, что пора купить.

### 1.3. Принятые решения

| № | Решение |
|---|---|
| Р-1 | Сайт для личного пользования. Пользователей несколько (владелец, позже друзья), у каждого своя учётная запись и **полностью независимый склад**. Ролей нет, кроме права владельца выдавать приглашения |
| Р-2 | Регистрация только по приглашению. Свободной регистрации нет |
| Р-3 | Жидкости учитываются в **миллилитрах точно**: владелец всегда отмеряет. Режима «примерно на глаз» нет |
| Р-4 | Инструменты учитываются в **штуках** |
| Р-5 | Учёт ведётся **по экземплярам**: каждая бутылка (или пачка инструментов) — отдельная запись со своим остатком, местом и ценой |
| Р-6 | Места хранения — справочник пользователя: номера коробок, полок, пакетов |
| Р-7 | Размещение — VPS **relay** (195.208.60.89). Сайт доступен **только через VPN**, как панель транзита |
| Р-8 | Адрес — `garage.north-flow.online`, HTTPS на существующем wildcard-сертификате. Название проекта и службы — `garage` |
| Р-9 | Стек — как у панели транзита: Go + SQLite + React/TypeScript, один бинарник со встроенным интерфейсом |
| Р-10 | Работа с компьютера и телефона, интерфейс в первую очередь под телефон, PWA |
| Р-11 | Интеграций с 1С, МойСклад и т. п. нет и не планируется. Сроков нет |
| Р-12 | Код хранится локально в рабочей директории и в репозитории на GitHub |
| Р-13 | Отмены покупки целиком нет: ошибки исправляются корректировкой экземпляров |

### 1.4. Термины

| Термин | Значение |
|---|---|
| Позиция | Товар в каталоге пользователя: «Шампунь Koch Chemie Gsf, 1000 мл», «Микрофибра 40×40 серая» |
| Экземпляр | Конкретная бутылка или пачка позиции, которая лежит у пользователя. У позиции может быть несколько экземпляров |
| Движение | Запись журнала: приход, расход, списание, перемещение, корректировка |
| Шаблон расхода | Набор «позиция — количество», который списывается одним действием («Мойка кузова») |
| Минимальный остаток | Порог по позиции; ниже него позиция попадает в список покупок |

## 2. Функциональные требования

### 2.1. ФТ-1. Учётные записи

- ФТ-1.1. Вход по логину и паролю. Сессия в cookie, срок 30 дней, продлевается при работе.
- ФТ-1.2. Первый пользователь (владелец) создаётся командой на сервере: `<бинарник> user add <логин>`.
- ФТ-1.3. Владелец создаёт одноразовую ссылку-приглашение со сроком действия 7 дней. По ней новый пользователь задаёт логин и пароль.
- ФТ-1.4. Смена пароля, выход со всех устройств.
- ФТ-1.5. Каждый пользователь видит и меняет **только свои** данные. Это проверяется на уровне каждого запроса к базе и покрывается тестами (раздел 6).

### 2.2. ФТ-2. Справочники

Все справочники — у каждого пользователя свои.

- ФТ-2.1. **Категории**: при регистрации заполняются начальным набором (шампуни, активная пена, очистители, полироли, защита, стёкла, кожа и пластик, шины и диски, микрофибра, губки и аппликаторы, щётки, прочее), дальше пользователь правит сам.
- ФТ-2.2. **Места хранения** — полностью редактируемый список:
  - добавить место («Коробка 3», «Полка 2», «Пакет 1»), в том числе прямо из формы покупки или перемещения;
  - переименовать: все экземпляры остаются на месте, меняется только название;
  - изменить порядок перетаскиванием;
  - архивировать (если в месте ничего не лежит) и вернуть из архива;
  - у места видно, сколько экземпляров в нём лежит, и можно открыть их список.
- ФТ-2.3. **Магазины**: название, необязательная ссылка (для интернет-магазина).
- ФТ-2.4. Запись справочника, на которую есть ссылки, не удаляется, а архивируется.

### 2.3. ФТ-3. Каталог позиций

Поля позиции:

| Поле | Обяз. | Примечание |
|---|---|---|
| Название | да | |
| Бренд | нет | с подсказкой из ранее введённых |
| Категория | да | |
| Единица | да | `мл` или `шт` |
| Размер упаковки | да | 500 мл в бутылке, 10 шт в пачке |
| Штрихкод | нет | заполняется вручную в v1.0, сканером — в v1.1 |
| Минимальный остаток | нет | в единицах позиции |
| Заметка | нет | разведение, особенности |

- ФТ-3.1. Позицию можно архивировать (больше не покупаю), история сохраняется.
- ФТ-3.2. Карточка позиции показывает:
  - суммарный остаток и экземпляры (место, остаток, вскрыт или нет);
  - историю покупок: дата, магазин, количество, цена, цена за 100 мл или за штуку;
  - историю расхода.

### 2.4. ФТ-4. Покупки (приход)

- ФТ-4.1. Покупка — это дата, магазин и одна или несколько строк: позиция, количество упаковок, цена за упаковку.
- ФТ-4.2. Из формы покупки можно сразу создать новую позицию, не уходя со страницы.
- ФТ-4.3. Каждая купленная упаковка становится экземпляром с полным остатком, статусом «запечатан» и местом хранения (по умолчанию — последнее место этой позиции).
- ФТ-4.4. Валюта — рубли. Суммы хранятся в копейках целым числом.
- ФТ-4.5. Покупка целиком не отменяется (Р-13). Ошибочно созданный экземпляр исправляется корректировкой остатка или списанием с причиной «ошибка ввода».

### 2.5. ФТ-5. Движения

- ФТ-5.1. **Расход**: позиция и количество (мл или шт). Количество вводится тремя способами (ФТ-5.8). Списывается из вскрытого экземпляра; если вскрытого нет — вскрывается самый старый по дате покупки. Если в экземпляре не хватает, остаток добирается из следующего, и пользователь видит, что бутылка закончилась.
- ФТ-5.2. Пользователь может явно выбрать экземпляр.
- ФТ-5.3. **Списание**: испорчено, выброшено, отдано — с причиной.
- ФТ-5.4. **Перемещение**: экземпляр в другое место хранения.
- ФТ-5.5. **Корректировка**: задать фактический остаток экземпляра. Разница пишется в журнал.
- ФТ-5.6. Каждое движение можно отменить в течение 10 секунд после ввода, а позже — удалить из журнала с пересчётом остатка.
- ФТ-5.7. Экземпляр с нулевым остатком получает статус «закончился» и пропадает из остатков, но остаётся в истории.
- ФТ-5.8. **Способы ввода количества** (на экране расхода, списания и корректировки):
  1. **Вписать вручную** — поле с цифровой клавиатурой.
  2. **Кнопки** `−50` `−10` `+10` `+50` меняют значение в поле. Для штук — `−1` `+1` `+5`. Значение не уходит ниже нуля и выше остатка (для расхода).
  3. **Шаблон** — ФТ-8, заполняет сразу несколько позиций.
  - Начальное значение в поле — количество, которое пользователь списывал в прошлый раз для этой позиции. Его можно сразу подтвердить.
  - Шаг кнопок (10 и 50) настраивается в профиле.

### 2.6. ФТ-6. Главный экран и поиск

- ФТ-6.1. Главный экран — строка поиска и список позиций с остатками. Поиск по названию, бренду, штрихкоду, без учёта регистра, с первой буквы.
- ФТ-6.2. Фильтры: категория, место, «ниже минимума», «нет в наличии».
- ФТ-6.3. В строке списка: название, суммарный остаток («1 вскрыт, 320 мл + 2 × 500 мл»), место.
- ФТ-6.4. Быстрые действия со строки: расход, покупка.

### 2.7. ФТ-7. Список покупок

- ФТ-7.1. Автоматически содержит позиции, у которых остаток ниже минимального.
- ФТ-7.2. Можно добавить позицию вручную и вычеркнуть купленное.
- ФТ-7.3. У каждой позиции — последняя цена и магазин, где брал дешевле.

### 2.8. ФТ-8. Шаблоны расхода (v1.0)

- ФТ-8.1. Шаблон — название и строки «позиция — количество».
- ФТ-8.2. Применение — экран с заполненными строками: количество можно поправить, строку убрать, затем одно подтверждение.
- ФТ-8.3. Показывается себестоимость применения по ценам экземпляров, из которых идёт списание.
- ФТ-8.4. Количество в строке при применении правится теми же способами, что в ФТ-5.8.
- ФТ-8.5. Шаблон можно создать из последнего расхода: «Сохранить как шаблон».
- ФТ-8.6. Если какой-то позиции не хватает, строка подсвечивается, остальные списываются после подтверждения.

### 2.9. ФТ-9. Сканер штрихкодов (v1.1)

- ФТ-9.1. Камера телефона из браузера. Используется библиотека на WebAssembly (zxing), потому что `BarcodeDetector` нет в Safari на iPhone.
- ФТ-9.2. Сканирование на главном экране открывает позицию или предлагает её создать.
- ФТ-9.3. Сканирование в форме позиции заполняет штрихкод.
- ФТ-9.4. Незнакомый код на главном экране: «Создать позицию» (штрихкод уже заполнен) или «Привязать к существующей» — выбор позиции, код записывается ей. Так коды проставляются уже заведённым позициям.
- ФТ-9.5. Если код есть у нескольких позиций — выбор из них.
- ФТ-9.6. Форматы: EAN-13, EAN-8, UPC-A/E, Code 128, QR. Библиотека (`zxing-wasm`) отдаётся с нашего сервера и загружается только при первом открытии сканера; в CSP добавляется `'wasm-unsafe-eval'`.
- ФТ-9.7. Видоискатель с анимацией поиска и подтверждения, фонарик (где поддерживается), ввод кода вручную. Нет доступа к камере — понятное объяснение и ручной ввод.

### 2.10. ФТ-10. Версия 1.2

Порядок работ: инвентаризация → отчёты → экспорт и импорт → фото. Telegram-бот — после v1.2 (ФТ-10.5).

**ФТ-10.1. Инвентаризация**
- ФТ-10.1.1. «Ещё → Инвентаризация» → выбор места → список действующих экземпляров этого места (позиция, остаток, объём).
- ФТ-10.1.2. По каждому экземпляру: «На месте» (остаток верный), исправить остаток (корректировка с причиной «Инвентаризация»), «Нет на месте» (списание всего остатка с причиной «Инвентаризация: не найден»), «В другом месте» (перемещение).
- ФТ-10.1.3. Прогресс «проверено N из M»; незавершённую проверку можно продолжить (состояние хранится в браузере до завершения).
- ФТ-10.1.4. Завершение: сводка изменений и отметка места «проверено ДД.ММ» (`locations.checked_at`), видна в списке мест и в выборе места для инвентаризации (давно не проверенные — сверху).
- ФТ-10.1.5. Все изменения — обычные движения с отменой, отдельного журнала инвентаризаций нет.

**ФТ-10.2. Отчёты** («Ещё → Отчёты»)
- ФТ-10.2.1. Период: месяц, квартал, год, свой (с–по).
- ФТ-10.2.2. Расходы на покупки за период: итог, по категориям, по магазинам, по месяцам (столбики).
- ФТ-10.2.3. Расход (списано) за период: по позициям в мл/шт и в деньгах (себестоимость), по месяцам.
- ФТ-10.2.4. История цен позиции — график цены за 100 мл / за шт по покупкам (в карточке позиции).
- ФТ-10.2.5. Графики — собственные (CSS/SVG), без внешних библиотек и без нарушения CSP.

**ФТ-10.3. Экспорт и импорт**
- ФТ-10.3.1. Экспорт всех своих данных одним файлом JSON (справочники, позиции, экземпляры, покупки, движения, шаблоны, список покупок, фото — base64).
- ФТ-10.3.2. Экспорт CSV для таблиц: позиции с остатками; покупки (строки); движения.
- ФТ-10.3.3. Импорт JSON своего экспорта — только в пустой склад (переезд, восстановление, перенос другу), до 100 МБ; экспорт можно скачать с фото или без. Непустой склад — отказ с объяснением. Проверка формата, версии, ссылок и сходимости остатков с журналом, всё в одной транзакции.

**ФТ-10.4. Фото позиции**
- ФТ-10.4.1. Одно фото на позицию: снять камерой или выбрать из галереи; в карточке позиции и миниатюрой в списке.
- ФТ-10.4.2. Сжимается в браузере до 1024 px по длинной стороне, JPEG, не больше 300 КБ.
- ФТ-10.4.3. Хранится в базе (BLOB), поэтому входит в ежедневный снимок и ночную копию без отдельной настройки. Сервер проверяет тип по содержимому (JPEG/PNG/WebP) и размер.
- ФТ-10.4.4. Отдаётся только владельцу позиции; замена и удаление фото.

**ФТ-10.5. Telegram-бот (после v1.2)**
- Остаток по названию, список покупок, уведомление о минимальном остатке. Требует бота от BotFather и токена — делает владелец.

## 3. Модель данных

У каждой таблицы пользовательских данных есть `user_id`. Все запросы фильтруются по нему.

| Таблица | Основные поля |
|---|---|
| `users` | id, login, password_hash, created_at |
| `sessions` | id (хеш токена), user_id, expires_at, user_agent |
| `invites` | id (хеш токена), created_by, expires_at, used_by |
| `categories` | id, user_id, name, sort, archived |
| `locations` | id, user_id, name, sort, archived |
| `stores` | id, user_id, name, url, archived |
| `products` | id, user_id, category_id, name, brand, unit (`ml`/`pcs`), package_size, barcode, min_stock, note, archived |
| `purchases` | id, user_id, store_id, date, note |
| `purchase_lines` | id, purchase_id, product_id, packages, price_per_package (коп.) |
| `units` (экземпляры) | id, user_id, product_id, purchase_line_id, location_id, initial_qty, remaining_qty, status (`sealed`/`open`/`finished`/`written_off`), opened_at, finished_at |
| `movements` | id, user_id, unit_id, type (`purchase`/`consume`/`writeoff`/`move`/`adjust`), qty_delta, from_location, to_location, reason, recipe_run_id, created_at |
| `shopping_items` | id, user_id, product_id, manual, done_at |
| `recipes`, `recipe_items` | шаблоны и их строки (позиция, количество) |
| `user_settings` | user_id, шаги кнопок количества |

- Количество — целое число: мл или шт.
- Остаток экземпляра хранится в `units.remaining_qty` и меняется в одной транзакции с записью в `movements`. Журнал позволяет пересчитать остаток и проверить его.
- Миграции схемы — нумерованные SQL-файлы, применяются при запуске.

## 4. Интерфейс

- И-1. Одностраничное приложение, в первую очередь под телефон (ширина от 360 px), на компьютере — та же раскладка шире.
- И-2. PWA: иконка на главный экран (`apple-touch-icon` и манифест), открывается без адресной строки, при запуске — фон темы. Офлайн-режим не нужен: без VPN сайт всё равно недоступен.
  - И-2.1. ## 5. Архитектура и развёртывание

### 5.1. Стек

| Часть | Технология |
|---|---|
| Сервер | Go 1.26, стандартная библиотека `net/http`, `modernc.org/sqlite` (без CGO), `golang.org/x/crypto` (argon2id) |
| База | SQLite, режим WAL, файл в `/var/lib/garage/` |
| Интерфейс | React 19, TypeScript, Vite, TanStack Query, react-router |
| Тесты | `go test`, Vitest |
| Сборка | Makefile по образцу панели транзита; интерфейс встраивается через `go:embed` |

### 5.2. Схема на relay

```
Телефон / Mac ──VPN (AmneziaWG)──► relay
                                    │
            AdGuard: garage.north-flow.online → 10.211.7.1
                                    │
            nginx 10.211.7.1:443 (wildcard *.north-flow.online)
                                    │ proxy_pass
                          127.0.0.1:8090 — служба garage
                                    │
                          /var/lib/garage/garage.db
```

- Р5.1. Приложение слушает только `127.0.0.1:8090`. Порт 8080 занят панелью.
- Р5.2. В nginx добавляется отдельный `server` с `listen 10.211.7.1:443` и своим `server_name`. Новых портов в файрволе не открывается.
- Р5.3. В AdGuard добавляется перезапись имени на `10.211.7.1`.
- Р5.4. Служба systemd от отдельного непривилегированного пользователя, `StateDirectory`, `ProtectSystem=strict`, `NoNewPrivileges`.
- Р5.5. Доверие к `X-Forwarded-For` и признак HTTPS — только от loopback, как в панели. nginx передаёт `Host`, `X-Real-IP` и `X-Forwarded-Proto $scheme` — по ним строится ссылка приглашения.
- Р5.6. Деплой: `make deploy HOST=relay` — сборка статического бинарника, копирование, перезапуск службы.

### 5.3. Резервное копирование

- Р5.7. Ежедневный снимок базы через `VACUUM INTO` (безопасно при работающей службе) в каталог, который забирает существующая ночная копия relay (`node-backup`, 23:05 МСК, шифрование age, отправка в Telegram).
- Р5.8. Хранятся 7 последних локальных снимков.
- Р5.9. Описана и проверена процедура восстановления из копии.

## 6. Требования к безопасности

- ТБ-1. Доступ только из VPN: nginx слушает адрес VPN, приложение — loopback.
- ТБ-2. Пароли — argon2id. Токены сессий и приглашений в базе только в виде хешей.
- ТБ-3. Cookie: `HttpOnly`, `Secure`, `SameSite=Strict`. Изменяющие запросы требуют заголовок `X-Requested-With` (защита от CSRF).
- ТБ-4. Ограничение попыток входа: 5 неудачных за 15 минут на логин и на адрес, далее пауза.
- ТБ-5. Изоляция пользователей:
  - все запросы содержат `user_id` из сессии, а не из тела запроса;
  - ссылки на чужие объекты (`product_id`, `location_id` и т. п.) отклоняются;
  - автотест проходит по всем эндпоинтам от имени второго пользователя и проверяет, что чужие данные недоступны.
- ТБ-6. Заголовки: строгая CSP без inline-скриптов, `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors 'none'`.
- ТБ-7. Проверка входных данных на сервере: длины строк, диапазоны количеств и цен, допустимые значения перечислений.
- ТБ-8. Зависимости npm ставятся строго по `package-lock.json` (`npm ci`), версии зафиксированы.
- ТБ-9. Секреты в репозиторий не попадают.

## 9. Риски

| Риск | Мера |
|---|---|
| Без VPN сайт недоступен — например, в магазине с выключенным VPN | Осознанное решение Р-7. VPN включается одним касанием |
| Сбой relay — недоступны и VPN, и учёт | Ночные копии; база переносится на любой сервер вместе с бинарником |
| Нагрузка на relay мешает VPN | Нагрузка ничтожная: один процесс Go, SQLite, единицы запросов в минуту |
| Точный ввод каждого расхода надоест | Быстрый расход с главного экрана, кнопки ±10/±50, шаблоны |

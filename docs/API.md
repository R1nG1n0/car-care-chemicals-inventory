# API garage

Справочник HTTP API сервера garage, версия 1.0: учётные записи, сессии и приглашения (ФТ-1), справочники, позиции, склад, покупки, расход, список покупок и шаблоны расхода (ФТ-2…ФТ-8). Сервер — `internal/web`, клиент — интерфейс `web/src`. Документ описывает текущее поведение кода; при расхождении источник истины — код.

## Общие правила

### Формат

- Все адреса API начинаются с `/api/`. Тела запросов и ответов — JSON в UTF-8 (`Content-Type: application/json; charset=utf-8`). У всех ответов API `Cache-Control: no-store`.
- Неизвестные поля в теле запроса игнорируются. Тело — не больше 64 КБ, иначе `413 {"error": "Слишком большой запрос"}`. Битый JSON или поле не того типа — `400 {"error": "Неверный формат запроса"}`.
- **Деньги** — целые копейки (`119000` = 1 190 ₽).
- **Количество** — целое число в единице позиции: мл (`unit: "ml"`) или шт (`unit: "pcs"`). Дробей нет.
- **Время** — секунды Unix (UTC), поля с суффиксом `_at`.
- **Даты покупок** — строка `"ГГГГ-ММ-ДД"`.
- Списки отдаются объектом с одним массивом: `{"categories": […]}`, `{"products": […]}` и т. д. Пустой список — `[]`, не `null`.
- Поле, которого может не быть, приходит как `null` (не пропускается). Исключение — `price_per_100`/`price_per_unit` у `PurchaseRow`: выводится только одно из двух.
- Неизвестный адрес под `/api/` — `404 {"error": "Нет такого метода API"}`. Неподдерживаемый метод — `405 {"error": "Метод не поддерживается"}` с заголовком `Allow`. Где есть `GET`, работает и `HEAD`.
- `{id}` в адресе — положительное целое; иначе `404` с тем же текстом, что и для несуществующей записи.

### Ошибки

Код HTTP и тело:

```json
{ "error": "Текст для человека по-русски", "field": "login" }
```

- `error` можно показывать пользователю как есть.
- `field` — имя поля формы, к которому относится ошибка; есть не всегда.
- Дополнительные поля: `retry_after` (секунды) у `429`, `available` у `409` при нехватке остатка.

| Код | Когда |
|---|---|
| `400` | Ввод не прошёл проверку (почти всегда с `field`), битый JSON, неверный параметр запроса |
| `401` | `{"error": "Нужно войти"}` — нет сессии или она истекла; неверный логин или пароль при входе |
| `403` | `{"error": "Запрос отклонён"}` — нет CSRF-заголовка; `{"error": "Доступно только владельцу"}`; неверный текущий пароль при смене |
| `404` | Записи нет **или она чужая** — ответ одинаковый |
| `405` | Метод не поддерживается адресом |
| `409` | Конфликт с состоянием данных: занятое имя, нехватка остатка, закончившийся экземпляр, архив места с экземплярами |
| `413` | Тело больше 64 КБ |
| `429` | Превышено число попыток входа |
| `500` | `{"error": "Внутренняя ошибка сервера"}` — подробности только в журнале сервера |

**Порядок проверок** на каждом адресе: метод (`405`) → CSRF-заголовок (`403`) → сессия (`401`) → права владельца (`403`) → тело и бизнес-проверки.

### Аутентификация и сессия

- Сессия — cookie `garage_session`: `HttpOnly`, `SameSite=Strict`, `Path=/`, `Max-Age` 30 дней, `Secure` (кроме конфигурации с `"insecure_cookies": true` — только для локальной разработки по http). В базе хранится только SHA-256 токена.
- Срок 30 дней продлевается при работе: если с последнего продления прошло больше часа, `expires_at` сдвигается на 30 дней от текущего момента и cookie выставляется заново (ФТ-1.1).
- Пришла cookie с недействительной или истёкшей сессией — ответ `401`, cookie стирается.
- Пароли хранятся хешем argon2id.
- Уровни доступа в справочнике ниже: **без входа**, **с входом** (по умолчанию — если не указано иное), **только владелец** (`is_owner: true`; остальным — `403 {"error": "Доступно только владельцу"}`).

### Защита от CSRF (ТБ-3)

Каждый запрос, кроме `GET`/`HEAD`, обязан нести заголовок `X-Requested-With: garage` — в том числе адреса без входа (`login`, `logout`, принятие приглашения). Без него — `403 {"error": "Запрос отклонён"}`. Чужая страница не может поставить этот заголовок без разрешения CORS, а CORS сервер не разрешает.

### Ограничение попыток входа (ТБ-4)

- 5 неудачных попыток за 15 минут (скользящее окно) — отдельно **на логин** (без учёта регистра) и **на адрес клиента**; блокирует то, что исчерпано раньше.
- Считаются неудачные `POST /api/auth/login` и неверный текущий пароль в `POST /api/auth/password`.
- При блокировке запрос отклоняется до проверки пароля (даже верного): `429 {"error": "Слишком много попыток. Повторите через 12 минут", "retry_after": 720}` и заголовок `Retry-After: 720`. `retry_after` — секунды, в тексте — минуты с округлением вверх.
- Успешный вход (и успешная смена пароля) сбрасывает счётчик логина; счётчик адреса не сбрасывается.
- Счётчики хранятся в памяти и обнуляются при перезапуске сервера.
- **Адрес клиента**: заголовкам прокси верим только если соединение пришло с loopback (nginx на том же сервере). Тогда берётся `X-Real-IP`, иначе правый адрес из `X-Forwarded-For`; с любого другого адреса — `RemoteAddr`, заголовки игнорируются.

### Изоляция пользователей (ТБ-5)

Все данные склада принадлежат пользователю. `user_id` берётся только из сессии, никогда из тела или адреса. Чужой или несуществующий `id` — в адресе, в теле (`product_id`, `location_id`, `store_id`, `unit_id`, `category_id`…) или в параметре `product_id` журнала — даёт одинаковый `404 {"error": "… не найдена"}`, чтобы нельзя было узнать, существует ли чужая запись. Исключение — фильтры списка позиций (`category_id`, `location_id`): чужой id даёт пустой список.

### Заголовки безопасности (ТБ-6)

На всех ответах (API и интерфейс):

```
Content-Security-Policy: default-src 'none'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; img-src 'self'; font-src 'self'; connect-src 'self'; manifest-src 'self'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: same-origin
Cross-Origin-Opener-Policy: same-origin
```

`'wasm-unsafe-eval'` (с версии 1.1) разрешает только компиляцию WebAssembly — модуля сканера штрихкодов `zxing-wasm` (ФТ-9.6); `eval` и `new Function` для скриптов по-прежнему запрещены. Файл модуля лежит в `assets/` рядом с остальной сборкой и отдаётся с `Content-Type: application/wasm`, внешних адресов нет.

Всё, что вне `/api/`, — файлы интерфейса; неизвестный путь без расширения отдаёт `index.html` (экранами управляет роутер в браузере), отсутствующий файл с расширением — `404`.

## Учётные записи

### Объекты

```json
// User
{ "id": 1, "login": "ringino", "is_owner": true }

// Settings — шаги кнопок количества (ФТ-5.8)
{ "step_small": 10, "step_large": 50 }

// Invite — без токена: токен хранится только хешем и виден один раз, при создании
{ "id": 7, "created_at": 1792140000, "expires_at": 1792744800, "status": "active" }
// status: active | used | expired | revoked (вычисляется: used важнее revoked, revoked важнее expired)
```

### Проверка ввода (ТБ-7)

| Поле | Правило | Ошибка |
|---|---|---|
| `login` | 3–32 символа: латиница, цифры, `_ . -`; уникален без учёта регистра | `400`, `field: "login"`, «Логин — от 3 до 32 символов: латиница, цифры, «_», «.», «-»»; занят — `409 {"error": "Этот логин уже занят", "field": "login"}` |
| `password` | 8–128 символов (считаются символы, не байты), корректный UTF-8 | `400`, `field: "password"`, «Пароль — от 8 до 128 символов» |
| `step_small` | целое 1–1000 | `400`, `field: "step_small"` |
| `step_large` | целое 1–5000, больше `step_small` | `400`, `field: "step_large"` |

## Вход и сессия

### `POST /api/auth/login` — без входа

```json
{ "login": "ringino", "password": "…" }
```

- `200 { "user": User, "settings": Settings }` + cookie сессии.
- `401 {"error": "Неверный логин или пароль"}` — одинаково для несуществующего логина и неверного пароля (время ответа тоже выравнивается).
- `429` — см. «Ограничение попыток входа».
- Логин сравнивается без учёта регистра.

### `GET /api/auth/me`

- `200 { "user": User, "settings": Settings }` или `401`.
- Интерфейс вызывает его при запуске, чтобы понять, показывать вход или приложение.

### `POST /api/auth/logout` — без входа

- Тело не нужно. `204`, сессия из cookie удалена, cookie стёрта. Без сессии — тоже `204`.

### `POST /api/auth/logout-all` (ФТ-1.4)

- `204`, удалены **все** сессии пользователя, включая текущую; cookie стёрта.

### `POST /api/auth/password` (ФТ-1.4)

```json
{ "current": "…", "new": "…" }
```

- `204`. Остальные сессии пользователя удаляются, текущая остаётся.
- `400` — новый пароль не проходит проверку (`field: "new"`). Проверяется до текущего пароля.
- `403 {"error": "Текущий пароль неверный", "field": "current"}` — `403`, а не `401`, чтобы интерфейс не решил, что сессия кончилась. Неудачи считаются в ограничение попыток по логину пользователя и адресу.
- `429` — исчерпан лимит попыток (проверяется первым).

### `PUT /api/auth/settings`

```json
{ "step_small": 10, "step_large": 50 }
```

- `200 Settings`. Оба поля обязательны (не переданное считается `0` → `400`).

## Приглашения (ФТ-1.3)

### `GET /api/invites` — только владелец

- `200 { "invites": [Invite, …] }` — последние 20 приглашений, созданных текущим владельцем, новые сверху.

### `POST /api/invites` — только владелец

- Тело не нужно. `201 { "invite": Invite, "url": "https://garage.north-flow.online/invite/<token>" }`.
- Токен — 32 случайных байта в base64url. Срок — 7 дней. **Ссылка показывается только в этом ответе**: в базе лежит хеш, восстановить её нельзя. Интерфейс показывает ссылку с кнопкой «Копировать» сразу после создания, а в списке — только срок и статус.
- `url` строится из заголовков запроса: хост — из `Host`; схема — `https`, если запрос пришёл по TLS или через nginx (соединение с loopback и `X-Forwarded-Proto: https`, либо без `X-Forwarded-Proto`, но с `X-Real-IP`/`X-Forwarded-For`); иначе `http` (локальная разработка).

### `DELETE /api/invites/{id}` — только владелец

- `204` — приглашение отозвано (`revoked_at`); повторный отзыв и отзыв истёкшего — тоже `204`.
- `404 {"error": "Приглашение не найдено"}` — нет, уже использовано или создано другим владельцем.

### `GET /api/invites/by-token/{token}` — без входа

- `200 { "expires_at": 1792744800 }` — приглашение действует.
- `404 {"error": "Приглашение не найдено или уже недействительно"}` — нет, истекло, использовано или отозвано.

### `POST /api/invites/by-token/{token}/accept` — без входа

```json
{ "login": "friend", "password": "…" }
```

- `201 { "user": User, "settings": Settings }` + cookie сессии. Новый пользователь — не владелец, со своим пустым складом.
- Ошибки: `404` — приглашение недействительно (проверяется **до** ввода: по мёртвой ссылке ошибок полей не будет); `400` — проверка ввода; `409 {"error": "Этот логин уже занят", "field": "login"}` — приглашение при этом не расходуется.
- Использование приглашения и создание пользователя — одна транзакция: одно приглашение — один пользователь, из двух одновременных принятий успешно ровно одно.
- При создании пользователя (здесь и в `garage user add`) заполняются: настройки `{step_small: 10, step_large: 50}` и категории по умолчанию (ФТ-2.1) в таком порядке — Шампуни `blue`, Активная пена `berry`, Очистители `olive`, Полироли и защита `ochre`, Стёкла `petrol`, Кожа и пластик `plum`, Шины и диски `slate`, Микрофибра `umber`, Губки и аппликаторы `umber`, Щётки `umber`, Прочее `slate`. Места и магазины — пустые.

## Справочники (ФТ-2)

```json
// Category
{ "id": 3, "name": "Шампуни", "color": "blue", "sort": 0, "archived": false, "products_count": 4 }
// Location
{ "id": 5, "name": "Коробка 3", "sort": 2, "archived": false, "units_count": 5, "checked_at": 1792140000 }
// checked_at — когда место проверяли инвентаризацией (unix-секунды); null — не проверялось
// Store
{ "id": 2, "name": "Автохим", "url": "", "archived": false }
```

| Адрес | Что делает |
|---|---|
| `GET /api/categories[?archived=1]` | `200 {categories: [Category]}` по `sort`, затем по имени. Без `archived=1` — только действующие, с ним — все вместе с архивными. `products_count` — неархивные позиции категории |
| `POST /api/categories` `{name, color}` | `201 Category`. `color` — один из восьми: `blue`, `berry`, `olive`, `ochre`, `petrol`, `plum`, `slate`, `umber` (иначе `400`, `field: "color"`); новая — в конец (`sort` = max+1) |
| `PATCH /api/categories/{id}` `{name?, color?, archived?}` | `200 Category`. Архивировать можно всегда: позиции остаются, но в формах архивная категория не предлагается |
| `POST /api/categories/reorder` `{ids: [...]}` | `204`. Новый порядок действующих: `ids` — ровно все действующие категории пользователя, каждая один раз, иначе `400 {"error": "Список устарел: обновите страницу", "field": "ids"}` |
| `GET /api/locations[?archived=1]` → `{locations: [Location]}`, `POST {name}`, `PATCH /{id} {name?, archived?}`, `POST /reorder {ids}` | То же для мест. `units_count` — экземпляры в статусах `sealed`/`open`. **Архивировать место с экземплярами нельзя**: `409 {"error": "В месте лежат экземпляры: 5. Сначала переложите их"}` |
| `GET /api/locations/{id}/units` | Инвентаризация (ФТ-10.1): `200 {units: [InventoryUnit]}` — экземпляры `sealed`/`open` **действующих** позиций в месте: `Unit` + `product: {id, name, brand, unit, package_size}`. Порядок: по названию позиции (без учёта регистра), вскрытые раньше запечатанных, по `id`. Чужое или несуществующее место — `404`; архивное — пустой список |
| `POST /api/locations/{id}/checked` | Инвентаризация: ставит `checked_at` = сейчас, без тела. `200 Location`. Чужое/несуществующее — `404`, архивное — `409` |
| `GET /api/stores[?archived=1]` → `{stores: [Store]}`, `POST {name, url?}`, `PATCH /{id} {name?, url?, archived?}` | То же для магазинов, порядок — по имени, без `reorder`. `url` — пусто или `http(s)://хост…`, до 500 символов (`400`, `field: "url"`) |

- Удаления справочников нет — только архив (ФТ-2.4).
- Имена — 1–40 символов после обрезки пробелов по краям (`400`, `field: "name"`).
- Имена уникальны у пользователя **без учёта регистра, включая кириллицу** («Коробка Новая» = «коробка новая») и вместе с архивными: `409 {"error": "Такое название уже есть", "field": "name"}`. Сменить регистр своего имени можно.
- Возврат из архива ставит категорию или место в конец порядка.
- Поля, не относящиеся к справочнику (`color` у места, `url` у категории), игнорируются.
- Проверка «в месте есть экземпляры» атомарна с записью.

## Позиции (ФТ-3, ФТ-6)

```json
// ProductSummary — строка списка остатков
{
  "id": 12, "category_id": 3, "name": "Koch Chemie Gsf", "brand": "Koch Chemie",
  "unit": "ml", "package_size": 1000, "barcode": "", "min_stock": 500, "note": "", "archived": false,
  "stock": {
    "total": 2320,          // сумма remaining_qty по sealed + open
    "open_qty": 320,        // остаток вскрытого (самого раннего по opened_at), null — вскрытого нет
    "open_capacity": 1000,  // его initial_qty, null — вскрытого нет
    "sealed_count": 2,      // запечатанных экземпляров
    "units_count": 3        // sealed + open
  },
  "low": false,             // min_stock задан и total < min_stock
  "location_ids": [5],      // места sealed/open экземпляров, без повторов, по возрастанию
  "last_consume_qty": 40    // сколько списали последним нажатием «Списать» (ФТ-5.8), см. ниже
}
```

`last_consume_qty` — сумма движений последней (по `id`) группы `batch_id` ручного расхода (`POST /api/consume`) этой позиции; расход по шаблону не учитывается; после отмены — предыдущее нажатие; `null` — не списывали.

| Адрес | Что делает |
|---|---|
| `GET /api/products` | `200 {products: [ProductSummary]}` по имени (без учёта регистра). ## Покупки и экземпляры (ФТ-4, ФТ-5)

| Адрес | Что делает |
|---|---|
| `POST /api/purchases` | Покупка (поля ниже). Одна транзакция: покупка, строки, **по экземпляру на каждую упаковку** (`initial = remaining = package_size` позиции, `sealed`), движение `purchase` (+package_size, `to_location_id`) на каждый экземпляр, отметка списка покупок. `201 {purchase: Purchase}` |
| `GET /api/purchases[?before={id}&limit=50]` | `200 {purchases: [PurchaseShort]}` — по `id`, новые сверху; `before` — id последней показанной покупки (следующая страница) |
| `GET /api/purchases/{id}` | `200 {purchase: Purchase}` |
| `POST /api/units` | **Ввод имеющегося остатка** — то, что уже лежит дома без покупки (поля ниже). `201 Unit` |
| `POST /api/units/{id}/move` `{location_id}` | Перемещение в своё действующее место. `200 Unit` |
| `POST /api/units/{id}/adjust` `{remaining_qty, reason?}` | Корректировка остатка (ФТ-5.5). `200 Unit` + поле `movement` |
| `POST /api/units/{id}/writeoff` `{qty?, reason}` | Списание (ФТ-5.3). `200 Unit` + поле `movement` |

**Тело покупки:**

```json
{ "date": "2026-10-02", "store_id": 2, "note": "",
  "lines": [{ "product_id": 12, "packages": 2, "price_per_package": 119000, "location_id": 5 }] }
```

| Поле | Правило | Ошибка |
|---|---|---|
| `date` | `ГГГГ-ММ-ДД`, существующая дата | `400`, `field: "date"` |
| `store_id` | необязательно; свой магазин (архивный тоже можно) | чужой — `404` |
| `note` | 0–500 символов | `400`, `field: "note"` |
| `lines` | 1–30 строк; позиция может повторяться | `400`, `field: "lines"` |
| `product_id` | своя позиция | `404` |
| `packages` | 1–100 | `400`, `field: "packages"` |
| `price_per_package` | 0–100000000 (до 1 000 000 ₽) | `400`, `field: "price_per_package"` |
| `location_id` | необязательно; своё действующее место | чужое — `404`; архивное — `400`, `field: "location_id"` |

Место экземпляров строки — `location_id` строки, иначе место последнего экземпляра этой позиции, лежащего в действующем месте, иначе `null`.

```json
// Purchase
{ "id": 8, "date": "2026-10-02", "store_id": 2, "store": "Автохим", "note": "", "total": 238000,
  "lines": [{ "id": 15, "product_id": 12, "product": "Koch Chemie Gsf", "packages": 2,
              "price_per_package": 119000, "unit_ids": [40, 41] }],
  "created_at": 1792000000 }
// store_id и store — null, если магазин не указан; total = Σ packages × price_per_package
// PurchaseShort
{ "id": 8, "date": "2026-10-02", "store": "Автохим", "total": 238000, "lines_count": 1 }
```

Отмены покупки целиком нет (Р-13): ошибки исправляются корректировкой и списанием.

**Ввод имеющегося остатка** `POST /api/units` `{product_id, remaining_qty, initial_qty?, location_id?}`:

- `initial_qty` по умолчанию — `package_size` позиции; 1–100000 (`400`, `field: "initial_qty"`). `remaining_qty` 1…initial (`400`, `field: "remaining_qty"`).
- Статус `sealed`, если остаток равен объёму, иначе `open` (`opened_at` = сейчас). Место — как у строки покупки.
- Движение `adjust` (+remaining, `reason: "Начальный остаток"`). `unit_price` у такого экземпляра — `null`.

**Перемещение** `move`: только у `sealed`/`open` (иначе `409 {"error": "Экземпляр уже закончился или списан"}`). Без `location_id` — `400`, `field: "location_id"`. Движение `move` (`qty_delta: 0`, `from_location_id`, `to_location_id`). В то же место — ничего не меняется, движения нет.

**Корректировка** `adjust`: `remaining_qty` 0…initial (`400`, `field: "remaining_qty"`; без поля — тоже `400`), `reason` 0–80 символов. Работает в любом статусе. Движение `adjust` на разницу. `0` → `finished`; больше 0 → `open` (у `sealed`, `finished` и `written_off`). Вернуть в `open` закончившийся или списанный экземпляр, чьё место в архиве, нельзя: `409 {"error": "Место экземпляра в архиве — сначала верните место из архива"}` (в архивном месте не может лежать экземпляров); без места — можно. Ответ — поля `Unit` плюс `movement` — созданное движение (`Movement`, для кнопки «Отменить»); тот же остаток — ничего не меняется, `movement: null`.

**Списание** `writeoff`: только у `sealed`/`open` (иначе `409`). `qty` по умолчанию — весь остаток, иначе 1–100000 (`400`, `field: "qty"`); больше остатка — `409 {"error": "Не хватает: есть 260 мл", "available": 260}`. `reason` 1–80 символов обязателен («Испорчено», «Ошибка ввода»…; `400`, `field: "reason"`). Движение `writeoff`; остаток 0 — `written_off`, частично списанный `sealed` становится `open`. Ответ — поля `Unit` плюс `movement` — движение списания.

Корректировка и списание, как и расход, обновляют экземпляр с условием на прочитанные остаток и статус: если его изменили между чтением и записью — `409 {"error": "Остаток изменился, повторите"}`, ничего не записано.

```json
// Ответ adjust и writeoff
{ "id": 40, "product_id": 12, "location_id": 5, "initial_qty": 1000, "remaining_qty": 280,
  "status": "open", "opened_at": 1792100000, "created_at": 1791900000, "unit_price": 119000,
  "movement": Movement }
```

## Расход и журнал (ФТ-5.1, ФТ-5.2, ФТ-5.6)

### `POST /api/consume` `{product_id, qty, unit_id?}`

Списать `qty` (1–100000, `400`, `field: "qty"`) своей позиции.

- Без `unit_id`: сначала вскрытые экземпляры (самый ранний `opened_at`, затем `id`), затем запечатанные — самый старый по дате покупки (у введённых без покупки — по дню создания), затем по `id`. С `unit_id` — начать с него (sealed/open этой позиции; другой позиции или чужой — `404`, закончившийся — `409`), дальше по тому же правилу.
- Не хватает в экземпляре — добирается из следующего. Запечатанный при первом расходе становится `open` (`opened_at` = сейчас); дошедший до 0 — `finished`.
- Всего меньше `qty` — `409 {"error": "Не хватает: есть 260 мл", "available": 260}` и ничего не списывается.
- Одна транзакция, по движению `consume` на каждый затронутый экземпляр, все — одна группа `batch_id`.
- `201 {movements: [Movement], product: ProductSummary, opened_unit_ids: [...], finished_unit_ids: [...], cost: 4760}`. `cost` — сумма `cost` движений; `null` — ни у одного нет цены.

### `POST /api/movements/revert` `{ids: [...]}`

Отмена движений (кнопка «Отменить» и удаление из журнала).

- `ids` — 1–100 различных id (повторы схлопываются), иначе `400`, `field: "ids"`.
- Все или ничего. Хоть один чужой или несуществующий — `404 {"error": "Движение не найдено"}`; разрешены только `consume`, `writeoff`, `adjust` — отмена `purchase` или `move` даёт `409`.
- Остаток экземпляра возвращается на сумму отменённых движений; выход за `0…initial_qty` — `409` («Отмените сначала более поздние движения»). Движения удаляются из журнала.
- Статус после отмены: остаток 0 → `finished` (например, отменён ввод имеющегося остатка); остаток равен объёму и по экземпляру не осталось движений расхода, списания и корректировки → снова `sealed` (`opened_at` = null) — движение «Начальный остаток» вскрытием не считается; иначе → `open` (в том числе `finished`/`written_off` с ненулевым остатком).
- Закончившийся или списанный экземпляр, который ожил бы (остаток больше 0) в архивном месте, — `409 {"error": "Место экземпляра в архиве — сначала верните место из архива"}`, ничего не отменяется.
- `200 {products: [ProductSummary]}` — обновлённые позиции.

### `GET /api/movements[?product_id=&before={id}&limit=50]`

- `200 {movements: [Movement]}` — по `id`, новые сверху. `product_id` — только движения этой позиции (чужая — `404`); `before` — id последнего показанного движения.

Общее для постраничных списков (`/api/purchases`, `/api/movements`): `limit` 1–100, по умолчанию 50, больше — `400`, `field: "limit"`; отрицательный или нечисловой параметр — `400` с `field`.

**Группы движений** (миграция 002, `movements.batch_id`): все движения одного запроса — покупки, расхода, применения шаблона — получают общий `batch_id` (id первого движения); одиночные движения (ввод остатка, перемещение, корректировка, списание) — сами себе группа. У старых записей `batch_id` = собственный `id`.

Проверка шаблона: `name` 1–60 символов (`400`, `field: "name"`), уникально без учёта регистра, включая кириллицу (`409 {"error": "Шаблон с таким названием уже есть", "field": "name"}`); `items` — 1–30 строк (`400`, `field: "items"`), `qty` 1–100000 (`field: "qty"`), позиции свои (`404`) и без повторов (`400`, `field: "items"`).

Все количества 0 — `400 {"error": "Нечего списывать: все количества равны нулю", "field": "items"}`. Одна транзакция: запись `recipe_runs` + расход по правилам `consume` (движения с `recipe_run_id`, одна группа `batch_id`). **Нехватка не ошибка** (ФТ-8.6): списывается сколько есть.

  "shortages": [{ "product_id": 12, "requested": 40, "consumed": 25 }], "cost": 4760 }

## Командная строка (ФТ-1.2)

```
garage [-config /etc/garage/config.json]                        # запустить сервер
garage -config /etc/garage/config.json user add <логин> [-owner] # создать пользователя
garage -config /etc/garage/config.json user passwd <логин>       # задать новый пароль
garage -config /etc/garage/config.json user list                 # логины, владелец, дата создания
garage -version                                                  # показать версию
```

- `-config` указывается до `user`; по умолчанию — `/etc/garage/config.json`.
- Пароль читается из терминала без отображения, дважды. Если ввод не терминал — одна строка из stdin (для скриптов).
- `user add`: логин и пароль проверяются по тем же правилам, что в API. **Первый** созданный пользователь становится владельцем, следующие — нет; флаг `-owner` делает владельцем явно. Настройки и категории по умолчанию заполняются так же, как при приглашении.
- `user passwd`: сбрасывает **все** сессии пользователя.
- `user list`: таблица «ЛОГИН / ВЛАДЕЛЕЦ / СОЗДАН» (время — местное).

# API garage

Договор между сервером (`internal/web`) и интерфейсом (`web/src`). Этап 1 — учётные записи, сессии, приглашения (ФТ-1). Разделы следующих этапов добавляются сюда же.

## Общие правила

- Все адреса начинаются с `/api/`. Тела запросов и ответов — JSON в UTF-8.
- **Ошибки** — код HTTP и тело `{"error": "Текст для человека по-русски"}`. Текст можно показывать пользователю как есть. Дополнительно может быть `"field": "login"` — имя поля формы, к которому относится ошибка.
- **Порядок проверок:** метод (`405` с заголовком `Allow`) → CSRF-заголовок (`403`) → сессия (`401`) → права владельца (`403 {"error": "Доступно только владельцу"}`). Тело запроса — не больше 64 КБ (`413`), битый JSON — `400 {"error": "Неверный формат запроса"}`.
- **Защита от CSRF (ТБ-3).** Каждый запрос, кроме `GET`/`HEAD`, обязан нести заголовок `X-Requested-With: garage`. Без него — `403 {"error": "Запрос отклонён"}`.
- **Сессия** — cookie `garage_session`: `HttpOnly`, `SameSite=Strict`, `Path=/`, `Max-Age` 30 дней, `Secure` (кроме конфигурации с `"insecure_cookies": true` — только для локальной разработки по http). Срок продлевается при работе: если с последнего продления прошло больше часа, `expires_at` сдвигается на 30 дней от текущего момента (ФТ-1.1).
- **Без сессии** любой адрес, кроме помеченных «без входа», отвечает `401 {"error": "Нужно войти"}`.
- **Владелец** — пользователь с `is_owner: true`. Адреса «только владелец» для остальных отвечают `403`.
- Время в ответах — секунды Unix (UTC), поле с суффиксом `_at`.

### Объекты

```json
// User
{ "id": 1, "login": "ringino", "is_owner": true }

// Settings — шаги кнопок количества (ФТ-5.8)
{ "step_small": 10, "step_large": 50 }

// Invite — без токена: токен хранится только хешем и виден один раз, при создании
{ "id": 7, "created_at": 1792140000, "expires_at": 1792744800, "status": "active" }
// status: active | used | expired | revoked
```

### Проверка ввода (ТБ-7)

| Поле | Правило | Ошибка |
|---|---|---|
| `login` | 3–32 символа: латиница, цифры, `_ . -`; без учёта регистра уникален | `400`, `field: "login"`; занят — `409` |
| `password` | 8–128 символов (считаются символы, не байты) | `400`, `field: "password"` |
| `step_small`, `step_large` | целые, 1–1000 и 1–5000, `step_small < step_large` | `400`, `field` |

## Вход и сессия

### `POST /api/auth/login` — без входа

```json
{ "login": "ringino", "password": "…" }
```

- `200 { "user": User, "settings": Settings }` + cookie сессии.
- `401 {"error": "Неверный логин или пароль"}` — одинаково для несуществующего логина и неверного пароля.
- `429 {"error": "Слишком много попыток. Повторите через 12 минут", "retry_after": 720}` (минуты округляются вверх) + заголовок `Retry-After`. Ограничение (ТБ-4): 5 неудачных попыток за 15 минут **на логин** и **на адрес клиента** — что наступит раньше. Успешный вход сбрасывает счётчик логина. Адрес клиента берётся из `X-Real-IP`/`X-Forwarded-For` только если соединение пришло с loopback (за nginx), иначе — `RemoteAddr`.

### `GET /api/auth/me`

- `200 { "user": User, "settings": Settings }` или `401`.
- Интерфейс вызывает его при запуске, чтобы понять, показывать вход или приложение.

### `POST /api/auth/logout`

- `204`, сессия удалена, cookie стёрта. Без сессии — тоже `204`.

### `POST /api/auth/logout-all` (ФТ-1.4)

- `204`, удалены **все** сессии пользователя, включая текущую; cookie стёрта.

### `POST /api/auth/password` (ФТ-1.4)

```json
{ "current": "…", "new": "…" }
```

- `204`. Остальные сессии пользователя удаляются, текущая остаётся.
- `400` — новый пароль не проходит проверку (`field: "new"`).
- `403 {"error": "Текущий пароль неверный", "field": "current"}` — `403`, а не `401`, чтобы интерфейс не решил, что сессия кончилась. Неудачи считаются в ограничение попыток логина.

### `PUT /api/auth/settings`

```json
{ "step_small": 10, "step_large": 50 }
```

- `200 Settings`, `400` при ошибке проверки.

## Приглашения (ФТ-1.3)

### `GET /api/invites` — только владелец

- `200 { "invites": [Invite, …] }` — последние 20, новые сверху.

### `POST /api/invites` — только владелец

- `201 { "invite": Invite, "url": "https://garage.north-flow.online/invite/<token>" }`.
- Схема в `url` — `https`, если запрос пришёл по TLS или через nginx (соединение с loopback и есть `X-Forwarded-Proto: https`, `X-Real-IP` или `X-Forwarded-For`); иначе `http` (локальная разработка). Хост — из `Host`.
- Токен — 32 случайных байта в base64url. Срок — 7 дней. **Ссылка показывается только в этом ответе**: в базе лежит хеш, восстановить её нельзя. Интерфейс показывает ссылку с кнопкой «Копировать» сразу после создания, а в списке — только срок и статус.
- Адрес в `url` строится из заголовков запроса (`Host`, схема — `https`, если запрос пришёл через nginx или по TLS).

### `DELETE /api/invites/{id}` — только владелец

- `204` — приглашение отозвано (`revoked_at`); повторный отзыв — тоже `204`. Использованное или выданное другим владельцем — `404`; не владелец — `403`.

### `GET /api/invites/by-token/{token}` — без входа

- `200 { "expires_at": 1792744800 }` — приглашение действует.
- `404 {"error": "Приглашение не найдено или уже недействительно"}` — нет, истекло, использовано или отозвано.

### `POST /api/invites/by-token/{token}/accept` — без входа

```json
{ "login": "friend", "password": "…" }
```

- `201 { "user": User, "settings": Settings }` + cookie сессии. Новый пользователь — не владелец, со своим пустым складом.
- При создании пользователю заполняются справочники по умолчанию (ФТ-2.1): категории с цветами — Шампуни `blue`, Активная пена `berry`, Очистители `olive`, Полироли и защита `ochre`, Стёкла `petrol`, Кожа и пластик `plum`, Шины и диски `slate`, Микрофибра `umber`, Губки и аппликаторы `umber`, Щётки `umber`, Прочее `slate`. Места и магазины — пустые.
- `404` — приглашение недействительно; `409 {"error": "Этот логин уже занят", "field": "login"}` — приглашение при этом не расходуется; `400` — проверка ввода.
- Использование приглашения и создание пользователя — одна транзакция: одно приглашение — один пользователь.

## Служебное

### `GET /api/health` — без входа

- `200 { "status": "ok", "version": "…" }`.

## Командная строка (ФТ-1.2)

```
garage -config /etc/garage/config.json user add <логин>       # создать владельца или пользователя
garage -config /etc/garage/config.json user passwd <логин>    # задать новый пароль, все сессии сбрасываются
garage -config /etc/garage/config.json user list              # логины, владелец, дата создания
```

- Пароль читается из терминала без отображения, дважды. Если ввод не терминал — одна строка из stdin (для скриптов).
- **Первый** созданный пользователь становится владельцем, следующие — нет (флаг `-owner` делает владельцем явно).
- Справочники по умолчанию заполняются так же, как при приглашении.
